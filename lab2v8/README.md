Звіт з лабораторної роботи №2
Тема роботи:
Клас із кількома конструкторами. Життєвий цикл об’єкта.

Мета роботи:
Навчитися реалізовувати перевантажені конструктори, дослідити порядок їх викликів та зрозуміти основи життєвого циклу об’єкта в C#.

Варіант: №8 (Клас Animal)
Репозиторій GitHub: OOP-Hlodovskyi/lab2v8

Що було зроблено:

Створено та налаштовано проєкт:
Створено консольний застосунок lab2v8 на платформі .NET.
Налаштовано структуру Git-репозиторію та завантажено проєкт на GitHub.

Реалізовано клас Animal (Варіант 8):
Приватні поля: _species (вид), _nickname (кличка), _age (вік).

Публічні властивості: додано властивості з валідацією (зокрема перевірка Age, щоб вік не міг бути від'ємним, та дефолтні значення для порожніх рядків).

Перевантажені конструктори: реалізовано кілька конструкторів з використанням ланцюгового виклику (: this(...)), що дозволило уникнути дублювання коду ініціалізації.

Метод класу: додано метод Speak(), який виводить інформацію про тварину та відповідний звук залежно від її виду.

Деструктор (фіналізатор): реалізовано деструктор ~Animal(), який сповіщає в консоль про вилучення об'єкта з пам'яті.

Продемонстровано життєвий цикл об'єктів у Main():
Створено 3 об'єкти класу Animal за допомогою різних перевантажених конструкторів.
Протестовано роботу валідації при спробі передати некоректний (від'ємний) вік.
Викликано метод Speak() для кожного об'єкта.
Викликано збирач сміття (GC.Collect() та GC.WaitForPendingFinalizers()), щоб примусово запустити фіналізацію та продемонструвати спрацювання деструкторів після втрати досяжності об'єктів.

Висновок
Висновок: Життєвий цикл об’єкта в C# охоплює його виділення в купі (heap) та ініціалізацію конструктором (використання ланцюгового виклику : this() дозволяє оптимізувати код і уникнути дублювання), період активного використання за наявності посилань, а також автоматичне вилучення збирачем сміття (Garbage Collector) із виконанням деструктора ~Animal() після того, як об'єкт стає недосяжним.
